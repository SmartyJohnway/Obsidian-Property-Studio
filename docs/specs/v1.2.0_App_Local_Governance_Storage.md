# Architecture Specification — App-Local Governance Storage & Persistence

**Document status:** Approved Architecture Freeze (M015)  
**Target release:** v1.2.0  
**Scope tier:** P0 (REQ-051)  
**Primary invariant:** The selected Obsidian Vault is strictly an untrusted, byte-for-byte read-only input source. All governance state must reside in application-local storage outside the Vault.

---

## 1. Storage Location & Directory Resolution

### 1.1 Base Directory Resolution
The application determines its governance storage root via the following resolution hierarchy:

```text
1. Environment Variable: PROPERTY_STUDIO_STORAGE_DIR (if explicitly set, e.g. during testing)
2. Windows Platform Default: %APPDATA%\ObsidianPropertyStudio\
3. Cross-Platform / Fallback: ~/.property_studio/
```

### 1.2 Layout & File Inventory
The storage root is organized into structured JSON entities:

```text
%APPDATA%/ObsidianPropertyStudio/
  ├── config/
  │   └── preferences.json                  # UI theme, locale, window preferences
  ├── glossary/
  │   └── user_glossary.json                # User Property Glossary overrides (REQ-041)
  ├── schemas/
  │   └── named_schemas.json                # Named Schema Library definitions (REQ-042)
  ├── scope_profiles/
  │   └── scope_expected_schemas.json       # Scope → Expected Schema assignments (REQ-044)
  ├── saved_checks/
  │   └── saved_relationship_checks.json    # User-defined Saved Relationship Checks (REQ-033)
  └── backups/
      └── auto_backup_YYYYMMDD_HHMMSS.json  # Pre-import and pre-mutation automatic snapshots
```

## 2. Vault Isolation Verification & Assertions

To guarantee that governance state is never written into a user's Vault:

1. **Path Containment Assertion:**  
   Before any read or write operation to app-local storage, the storage engine verifies:
   $$\text{Path}(\text{StorageDir}) \cap \text{Path}(\text{SelectedVaultDir}) = \emptyset$$
   Specifically, `StorageDir` must not be equal to, a child of, or a parent of `SelectedVaultDir`.
2. **Pre/Post File Manifest Validation:**  
   Vault integrity test suites (`tests/test_v11_vault_readonly.py`, `tests/test_v12_readonly.py`) verify $0$ created, $0$ modified, and $0$ deleted files in the Vault across all storage operations.

## 4. Atomic Write & Concurrency Protection

To prevent corruption during sudden application termination or power loss:

1. **Write-to-Temp and Atomic Replace:**  
   - Serialize payload to `{filename}.tmp.{pid}` in the target directory.
   - Perform atomic replacement via Python `os.replace()` (atomic POSIX `rename` and Windows `MoveFileExW` with `MOVEFILE_REPLACE_EXISTING`).
2. **Directory Existence Guarantee:**  
   Parent directories are ensured recursively with `os.makedirs(exist_ok=True)` before write.

---

## 5. Fail-Closed Handling & Auto-Backup Strategy

1. **Corrupt File Quarantine:**  
   If a storage file cannot be parsed or fails schema validation on load:
   - The corrupted file is renamed to `{filename}.corrupted.{timestamp}` for user forensics.
   - The application fails closed with a structured diagnostic error and instructions to restore from backup or start clean.
   - It **never silently overwrites** or resets corrupted user data.
2. **Automatic Snapshots:**  
   Before applying any batch update, import, or deletion, the storage engine copies affected files to `backups/auto_backup_{timestamp}.json`.
