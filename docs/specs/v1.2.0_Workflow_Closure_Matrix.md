# Architecture Specification — Workflow Closure Matrix & Baseline CTA Contracts

**Document status:** Approved Architecture Freeze (M015)  
**Target release:** v1.2.0  
**Scope tier:** P0 (REQ-040)  
**Core invariant:** Zero Dead-End CTAs. Every primary user action must reach a deterministic visible result, a terminal artifact, or an explicit next action.

---

## 1. Workflow Closure Contract Definition

A primary Call-to-Action (CTA) is defined as a primary user-interactive trigger that initiates state transitions, data processing, navigation, or output generation.

For every primary CTA, the following 13 contract attributes are formally specified and tracked:

```text
1. CTA ID: Unique stable identifier (e.g. CTA-REC-001)
2. Module: Owning product area
3. Starting State: Required prerequisites and context
4. User Intent: What the user seeks to accomplish
5. Action: UI trigger element (button, menu, hotkey)
6. State Transferred: Explicit parameters passed across boundaries
7. Backend/Core Operation: Deterministic processing engine executed
8. Visible Result: Primary UI rendering upon completion
9. Terminal Outcome / Next Action: Clipboard artifact, report, or explicit forward routing
10. Failure Path: Fail-closed error presentation and recovery action
11. Automated Test ID: Regression test validating the flow
12. Human Verification: Manual acceptance criteria on Windows 10
13. Formal Status: PASS | IN_PROGRESS | PLANNED | HOLD
```

## 3. CTA Failure Modes & Fail-Closed Behavior

1. **Corrupt / Malformed Frontmatter:**  
   `Note Properties Workspace` disables editing and Copy actions, surfacing explicit YAML line errors (`V11-007`, `V11-008`).
2. **Invalid / Incompatible AI Proposal:**  
   `AI Proposal Review` highlights specific schema syntax violations and missing keys without crashing (`V12-AIP-003`).
3. **Corrupted Governance Profile Import:**  
   `Profile Import` aborts with an explanatory error, preserving existing state without partial overwrites (`V12-PROF-003`).
